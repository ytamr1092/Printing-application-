## ما يسجله التطبيق فعليًا

### معلومات الهاتف والتطبيق

يسجل التقرير:

- نظام التشغيل والمنصة.
- عنوان IP للهاتف.
- نوع الشبكة.
- هل الاتصال بالشبكة قائم أم لا.

### إعدادات الطباعة وقت إنشاء التقرير

يسجل:

- عنوان IP الموجود في خانة الطابعة.
- عدد النسخ.
- الطباعة على وجه واحد أو وجهين.
- الوضع الملون أو الأبيض والأسود.

ويضيف ملاحظة صحيحة فنيًا: RAW/9100 يرسل الملف كما هو، ولذلك إعدادات النسخ والوجهين والألوان لا تُفرض عبر RAW؛ هذه الإعدادات تُرسل في طلب IPP فقط.

## الاختبارات التي ينفذها التطبيق

| الاختبار | الطريقة | معنى النتيجة |
|---|---|---|
| RAW 9100 | اتصال TCP حقيقي | هل يقبل المنفذ اتصالًا فقط؛ لا يثبت تفسير PDF |
| LPD 515 | اتصال TCP حقيقي | هل المنفذ مفتوح؛ لا يثبت اسم الطابور أو نجاح جلسة LPD |
| IPP 631 | طلب IPP Get-Printer-Attributes | يختبر بروتوكول IPP الحقيقي وليس HTML |
| IPP TLS 443 | طلب IPP عبر HTTPS | قد يفشل بسبب شهادة الطابعة الذاتية أو إعداد HTTPS |
| IPP 80/8000/8080 | طلب IPP على منافذ بديلة | يوضح إن كانت الطابعة تستجيب على مسار غير قياسي |
| eSCL 80 | ScannerCapabilities | يختبر واجهة السكانر المحلية عبر HTTP |
| eSCL 443 | ScannerCapabilities عبر HTTPS | يختبر eSCL المشفر |
| eSCL Status | ScannerStatus | يقرأ حالة السكانر عند رجوع XML صالح |
| eSCL Capabilities | ScannerCapabilities | يقرأ الموديل وصيغ المستندات إن ظهرت |
| Web 80 | `/wlmeng/index.htm` | يختبر نفس صفحة Command Center RX التي تفتح من المتصفح |

## معلومات IPP التي يحاول التطبيق استخراجها

من رد `Get-Printer-Attributes` يحاول التطبيق قراءة:

- موديل الطابعة من `printer-make-and-model`.
- صيغ المستندات المعلنة مثل:
  - `application/pdf`
  - `image/jpeg`
  - `image/urf`
  - `image/pwg-raster`
  - `application/postscript`
  - `application/octet-stream`
  - `application/vnd.hp-PCL`

وجود صيغة في الرد يعني أن الطابعة أعلنت دعمها لها عبر IPP، وليس بالضرورة أن RAW/9100 يقبل نفس الصيغة.

## سجل محاولات الطباعة والمسح

يحتفظ التطبيق بآخر 40 حدثًا في جلسة التطبيق. من أمثلتها:

```text
[print] RAW 9100 accepted (application/pdf, <bytes> bytes)
[print] RAW 9100 failed (application/pdf, <bytes> bytes)
[print] IPP result: true
[print] IPP result: unconfirmed
[print] fell back to the system print dialog
[scan] failed: <reason>
```

قبول TCP في RAW لا يعني وحده خروج الورقة؛ يجب التحقق من الطابعة فعليًا، لأن الملف قد يكون PDF غير مدعوم كلغة طباعة مباشرة.

## طريقة الحصول على النتيجة الحقيقية

1. ثبّت النسخة المبنية من آخر `main`.
2. اتصل بنفس شبكة Wi‑Fi التي توجد عليها الطابعة.
3. افتح مساحة **السكانر**.
4. اكتب:
   ```text
   192.168.1.102
   ```
5. اضغط **تشخيص الطابعة والسكانر**.
6. انتظر انتهاء الفحص.
7. اضغط **إرسال آخر تقرير تشخيص**.
8. أرسل ملف `PrintPilot-diagnosis-....txt` الناتج.
9. نفّذ بعدها تجربة طباعة PDF صغير، ثم شغّل التشخيص مرة أخرى حتى يظهر سجل محاولة الطباعة.

## الاستنتاج الحالي

الكود يحتوي الآن على فصل واضح بين:

- اتصال TCP.
- رد HTTP.
- رد IPP الحقيقي.
- رد eSCL/XML.
- نتيجة قبول مهمة الطباعة.
- نتيجة خروج الورقة فعليًا.

لكن لا يمكن الجزم بأن الطباعة تعمل أو أن السكانر يعمل من خلال الكود وحده. التقرير الحقيقي النهائي يجب أن يحتوي على نتائج تشغيل الهاتف على عنوان `192.168.1.102`، بالإضافة إلى نتيجة ورقة مطبوعة ومسح فعلي.
